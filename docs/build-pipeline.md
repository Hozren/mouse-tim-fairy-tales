# Сборка сказок в GitHub Actions

Цель: воспроизводимо собирать EPUB и PDF каждой новой сказки и публиковать их как отдельный GitHub Actions artifact только при изменениях внутри директории этой сказки.

Источники: структура `generated/`, `book.json`, сборщики из `.skills/tim-story-production/scripts/`.

Создано: 2026-11-25. Автор/агент: Аркан.

## Автоматический запуск

Workflow `.github/workflows/build-stories.yml` запускает лёгкий этап обнаружения на каждом `push` и `pull_request`.

Для обычного push сравниваются точные снимки `before` и `after`. Для pull request используется merge-base базовой и рабочей веток. Для новой ветки используется merge-base с default branch, а для первой ветки или несвязанной истории — пустое Git-дерево.

Из diff выбираются только существующие директории вида `generated/<story-slug>/`. Изменения файлов непосредственно в `generated/` игнорируются. Удалённые директории не собираются.

Если директория сказки не менялась, для неё не создаётся build job и не публикуется artifact. Изменения общих сборщиков и workflow сами по себе также не пересобирают сказки; для этого предназначен ручной запуск.

## Ручной запуск

`workflow_dispatch` формирует матрицу из всех непосредственных директорий сказок в `generated/` и выполняет полную пересборку.

## Результат

Для каждой сказки запускается отдельный matrix job. Он собирает во временный `_dist/<story-slug>/` два файла:

- `<story-slug>.epub`;
- `<story-slug>.pdf`.

Полноразмерные PNG остаются мастер-исходниками. В EPUB и PDF включаются оптимизированные progressive JPEG-производные с параметрами из `book.json`, поэтому публикационные файлы не дублируют весь вес мастер-иллюстраций. Стандартный экранный профиль проекта — 1100 пикселей по длинной стороне и качество 76; повышать его следует только для отдельной печатной сборки.

Они публикуются одним artifact с именем `story-<story-slug>-<run-id>-<run-attempt>` и хранятся 30 дней. Исходники, промпты и промежуточные файлы в artifact не входят.

Workflow имеет только разрешение `contents: read`, не использует секреты и не пишет в репозиторий.

## Постоянные публикации (2026-11-25)

Локальные сборщики по умолчанию пишут в `_dist/<story-slug>/`; `--output` позволяет переопределить путь. Сборки и ZIP в `generated/` игнорируются Git. В Git хранятся исходники и мастер-иллюстрации, а не публикационные бинарники.

Workflow `release-books.yml` запускается при push тега `books-*`, собирает EPUB/PDF всех сказок и публикует их в GitHub Releases без 30-дневного срока artifacts. Сборка выполняет встроенные проверки обоих форматов. Релиз создаётся черновиком и становится опубликованным только после загрузки всех файлов. В отличие от обычного CI, только этот workflow имеет `contents: write`.

Публикация новой версии: после коммита и push исходников создать уникальный тег, например `git tag books-2026-11-25`, затем `git push origin books-2026-11-25`. Готовые версии: https://github.com/Hozren/mouse-tim-fairy-tales/releases.
